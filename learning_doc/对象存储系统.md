# 对象存储系统详解

> 基于阿里云 OSS 构建对象存储能力，支持两种上传模式：**后端流式上传**（头像）和**预签名 PUT URL 直传**（知文内容/图片/视频），实现了节省后端带宽的高效媒体上传方案。

---

## 一、模块结构

```
storage/
├── api/
│   ├── StorageController.java       # REST 接口（生成预签名 URL）
│   └── dto/
│       ├── PresignRequest.java      # 预签名请求 DTO
│       └── PresignResponse.java     # 预签名响应 DTO（url/objectKey/expireAt）
├── config/
│   └── OssProperties.java           # OSS 配置属性
└── OssStorageService.java           # OSS 核心操作封装
```

## 二、两种上传模式

### 2.1 模式一：后端流式上传（头像）

```
前端                           后端                          OSS
 │  POST /api/v1/profile/avatar │                            │
 │  multipart/form-data         │                            │
 │─────────────────────────────>│                            │
 │                              ├─ 1. 解析 MultipartFile     │
 │                              ├─ 2. 生成 objectKey         │
 │                              │    = {folder}/{userId}-{ts}{ext}
 │                              ├─ 3. OSSClient.putObject()  │
 │                              │─────────────────────────>  │
 │                              │                            │ 写入 OSS
 │                              │<──────────────────────────-│
 │                              ├─ 4. 生成公共访问 URL       │
 │                              ├─ 5. UPDATE users.avatar    │
 │<─────────────────────────────│                            │
 │  {avatarUrl}                 │                            │
```

**特点**：
- 文件经过后端中转（占用后端带宽和内存）
- 适合小文件（头像通常 < 2MB）
- 后端可以对文件进行校验（类型/大小）

### 2.2 模式二：预签名 PUT 直传（知文内容/图片/视频）

```
前端                           后端                          OSS
 │                              │                            │
 │  POST /api/v1/storage/presign│                            │
 │  {objectKey, contentType,    │                            │
 │   expiresInSeconds=600}      │                            │
 │─────────────────────────────>│                            │
 │                              ├─ OssStorageService         │
 │                              │  .generatePresignedPutUrl()│
 │                              │   OSSClient               │
 │                              │   .generatePresignedUrl()  │
 │<─────────────────────────────│                            │
 │  {url: "https://oss.xxx/...?│                            │
 │   OSSAccessKeyId=...&..."}   │                            │
 │                              │                            │
 │  PUT {presignedUrl}          │                            │
 │  Content-Type: text/markdown │                            │
 │  Body: <文件内容>            │                            │
 │─────────────────────────────────────────────────────────>│
 │                              │                            │ 直接写入
 │<─────────────────────────────────────────────────────────-│
 │  200 OK (ETag: "abc123")     │                            │
 │                              │                            │
 │  POST /api/v1/knowposts/{id}/content
 │  {objectKey, etag, size,     │                            │
 │   sha256}                    │                            │
 │─────────────────────────────>│                            │
 │                              ├─ confirmContent()          │
 │                              │   写入 contentUrl/etag/sha256
 │<─────────────────────────────│                            │
```

**特点**：
- 文件直传 OSS，不经过后端（节省后端带宽）
- 适合大文件（视频、高分辨率图片）
- 后端只负责颁发签名，不承担传输负担
- 前端必须使用签名中指定的 Content-Type 进行上传

## 三、OssStorageService 核心实现

### 3.1 配置属性（OssProperties）

```yaml
oss:
  endpoint: oss-cn-beijing.aliyuncs.com   # OSS 服务端点（地域）
  access-key-id: xxx                       # 访问密钥 ID
  access-key-secret: yyy                   # 访问密钥 Secret
  bucket: zhiguangapp                      # 存储桶名称
  folder: posts                            # 根目录前缀
  public-domain: https://cdn.zhiguang.cn  # 可选：CDN 自定义域名
```

### 3.2 uploadAvatar（后端上传）

```java
public String uploadAvatar(long userId, MultipartFile file) {
    ensureConfigured();  // 配置完整性校验

    // 生成唯一 objectKey
    String objectKey = props.getFolder() + "/" + userId + "-"
                     + Instant.now().toEpochMilli() + ext;

    // 创建 OSS 客户端（每次请求创建，用完关闭）
    OSS client = new OSSClientBuilder().build(
        props.getEndpoint(),
        props.getAccessKeyId(),
        props.getAccessKeySecret()
    );

    try {
        PutObjectRequest request = new PutObjectRequest(
            props.getBucket(),
            objectKey,
            file.getInputStream()
        );
        client.putObject(request);
    } finally {
        client.shutdown();  // 释放资源
    }

    return publicUrl(objectKey);  // 返回公共访问 URL
}
```

### 3.3 generatePresignedPutUrl（预签名生成）

```java
public String generatePresignedPutUrl(String objectKey, String contentType, int expiresInSeconds) {
    ensureConfigured();
    OSS client = new OSSClientBuilder().build(...);
    try {
        Date expiration = new Date(System.currentTimeMillis() + expiresInSeconds * 1000L);
        GeneratePresignedUrlRequest request = new GeneratePresignedUrlRequest(
            props.getBucket(),
            objectKey,
            HttpMethod.PUT           // 签名的 HTTP 方法必须是 PUT
        );
        request.setExpiration(expiration);
        if (contentType != null && !contentType.isBlank()) {
            request.setContentType(contentType);  // 签名绑定 Content-Type
        }
        URL url = client.generatePresignedUrl(request);
        return url.toString();
    } finally {
        client.shutdown();
    }
}
```

**关键细节**：
- 预签名 URL 包含签名参数（`OSSAccessKeyId`、`Expires`、`Signature`）
- 前端 PUT 时必须使用**与签名一致**的 Content-Type，否则 OSS 验签失败
- 有效期建议 300~900 秒，避免太短导致上传超时，也避免太长存在安全风险

### 3.4 publicUrl 生成逻辑

```java
private String publicUrl(String objectKey) {
    if (props.getPublicDomain() != null && !props.getPublicDomain().isBlank()) {
        // 使用自定义 CDN 域名（如 https://cdn.zhiguang.cn/posts/xxx.jpg）
        return props.getPublicDomain().replaceAll("/$", "") + "/" + objectKey;
    }
    // 使用 OSS 默认域名（如 https://zhiguangapp.oss-cn-beijing.aliyuncs.com/posts/xxx.jpg）
    return "https://" + props.getBucket() + "." + props.getEndpoint() + "/" + objectKey;
}
```

## 五、内容 ETag 与 SHA256

上传完成后，前端需要将 OSS 返回的 ETag 和自行计算的 SHA256 传给后端（`confirmContent`）：

```json
POST /api/v1/knowposts/{id}/content
{
    "objectKey": "posts/post/987654321/content.md",
    "etag": "\"d41d8cd98f00b204e9800998ecf8427e\"",
    "size": 12345,
    "sha256": "abc123def456..."
}
```

这两个值在 RAG 系统中用于**内容变更指纹检测**：
- `ETag`：OSS 自动计算，MD5 值，文件变化时自动更新
- `SHA256`：前端或后端计算，比 MD5 更安全（防碰撞），优先用于指纹比较

## 七、前端直传完整流程示例

```
// 1. 向后端申请预签名 URL
const { url, objectKey } = await api.post('/storage/presign', {
    objectKey: `posts/post/${postId}/content.md`,
    contentType: 'text/markdown',
    expiresInSeconds: 600
});

// 2. 前端直接 PUT 上传到 OSS
const response = await fetch(url, {
    method: 'PUT',
    headers: {
        'Content-Type': 'text/markdown'  // 必须与签名时的 contentType 一致
    },
    body: markdownContent
});
const etag = response.headers.get('ETag');

// 3. 通知后端上传完成
await api.post(`/knowposts/${postId}/content`, {
    objectKey,
    etag,
    size: markdownContent.length,
    sha256: await computeSha256(markdownContent)
});
```

## 八、设计亮点与学习要点

1. **预签名直传架构**：后端零流量承受、OSS 直接承担上传带宽，特别适合视频等大文件上传场景。这是 S3 兼容存储的标准用法（S3 Presigned URL）
2. **两种模式的权衡**：头像使用后端上传是因为文件小且需要后端校验（防止上传非图片）；知文内容使用直传是因为文件大（视频可达GB级）
3. **Content-Type 绑定**：预签名 URL 绑定特定 Content-Type，防止攻击者用同一 URL 上传不同类型文件
4. **ETag + SHA256 双重指纹**：ETag 由 OSS 提供（无需额外计算），SHA256 更安全防碰撞，双重保障 RAG 系统的内容变更检测
5. **每次创建 OSSClient**：阿里云 SDK 推荐使用后关闭，避免连接泄漏。生产环境中可考虑连接池复用
6. **自定义 CDN 域名**：配置 `public-domain` 后使用 CDN 加速访问，降低源站流量，提升媒体资源加载速度
