# 认证系统详解

> 基于 Spring Security OAuth2 Resource Server + JWT（RS256）的双令牌认证系统，支持手机号/邮箱注册与登录，实现 15 分钟 Access Token + 7 天 Refresh Token 的安全会话管理，并提供即时令牌撤销能力。

## 二、核心流程详解

### 2.1 注册流程

```
前端                          后端
 │  POST /api/v1/auth/register  │
 │─────────────────────────────>│
 │  {identifierType, identifier, code, password?, agreeTerms}
 │                              │
 │                              ├─ 1. 校验 agreeTerms（必须同意）
 │                              ├─ 2. 格式校验：手机号/邮箱正则
 │                              ├─ 3. normalizeIdentifier（去空格/转小写）
 │                              ├─ 4. 检查标识是否已存在（查 users 表）
 │                              ├─ 5. 验证码校验：verificationService.verify(REGISTER, ...)
 │                              │      └─ Redis 取验证码 → 比对 → 标记消费
 │                              ├─ 6. 如提供密码：validatePassword（长度+字母数字）
 │                              │      → BCrypt encode
 │                              ├─ 7. 创建用户（insert users）
 │                              │      nickname = "知光用户" + UUID前8位
 │                              ├─ 8. jwtService.issueTokenPair(user)
 │                              │      ├─ Access Token (RS256, 15min)
 │                              │      └─ Refresh Token (RS256, 7day)
 │                              ├─ 9. storeRefreshToken → Redis 白名单
 │                              ├─ 10. loginLogService.record("REGISTER", "SUCCESS")
 │                              └─ 11. 返回 {user, token}
 │<─────────────────────────────│
```

### 2.2 登录流程

```
前端                          后端
 │  POST /api/v1/auth/login     │
 │─────────────────────────────>│
 │  {identifierType, identifier, password? | code?}
 │                              │
 │                              ├─ 1. 格式校验 + normalize
 │                              ├─ 2. 查找用户（按 phone 或 email）
 │                              │     → 不存在：抛 IDENTIFIER_NOT_FOUND
 │                              │
 │                              ├─ 密码登录（channel=PASSWORD）
 │                              │   ├─ 检查 passwordHash 非空
 │                              │   ├─ BCrypt.matches(password, hash)
 │                              │   └─ 不匹配：记录 FAILED 审计 → 抛 INVALID_CREDENTIALS
 │                              │
 │                              ├─ 验证码登录（channel=CODE）
 │                              │   └─ verificationService.verify(LOGIN, ...)
 │                              │
 │                              ├─ 签发令牌对
 │                              ├─ 存 Refresh Token 白名单
 │                              ├─ 记录 SUCCESS 审计
 │                              └─ 返回 {user, token}
 │<─────────────────────────────│
```

### 2.3 令牌刷新流程

```
前端                          后端
 │  POST /api/v1/auth/token/refresh
 │  {refreshToken}             │
 │─────────────────────────────>│
 │                              ├─ 1. jwtService.decode(refreshToken)
 │                              │     → 解码失败：抛 REFRESH_TOKEN_INVALID
 │                              ├─ 2. 校验 token_type == "refresh"
 │                              ├─ 3. 提取 userId + tokenId
 │                              ├─ 4. refreshTokenStore.isTokenValid(userId, tokenId)
 │                              │     → Redis 白名单检查；不存在：抛 REFRESH_TOKEN_INVALID
 │                              ├─ 5. 查找用户（确认账号仍存在）
 │                              ├─ 6. 签发新令牌对
 │                              ├─ 7. revokeToken(userId, oldTokenId)  # 撤销旧令牌
 │                              ├─ 8. storeToken(userId, newTokenId)   # 存储新令牌
 │                              └─ 返回新 {accessToken, refreshToken}
 │<─────────────────────────────│
```

**令牌轮换（Rotation）**：每次刷新都会撤销旧 Refresh Token 并颁发新令牌对，防止令牌重放攻击。

### 2.4 登出流程

```
POST /api/v1/auth/logout
{refreshToken}
  │
  ├─ 安全解码 refreshToken（失败则静默忽略，不报错）
  ├─ 若 token_type == "refresh"
  │   └─ refreshTokenStore.revokeToken(userId, tokenId)
  │       └─ Redis DEL：{userId}:{tokenId} 键
  └─ 下次使用该 Refresh Token 刷新时将失败
```

### 2.5 发送验证码流程

```
POST /api/v1/auth/send-code
{identifierType, identifier, scene}
  │
  ├─ 格式校验 + normalize
  ├─ 存在性检查（与场景匹配）：
  │   ├─ REGISTER 场景：标识不能已存在
  │   └─ LOGIN/RESET_PASSWORD 场景：标识必须存在
  ├─ verificationService.sendCode(scene, identifier)
  │   ├─ 频率限制（Redis）：同一标识 60 秒内不允许重发
  │   ├─ 每日上限（Redis）：同一标识每日最多发送 N 次
  │   ├─ 生成 6 位随机验证码
  │   ├─ Redis 存储：key=verify:{scene}:{identifier}, TTL=300s
  │   └─ codeSender.send()（开发环境：打日志；生产环境：短信/邮件）
  └─ 返回 {identifier, scene, expireSeconds}
```

### 2.6 重置密码流程

```
POST /api/v1/auth/password/reset
{identifierType, identifier, code, newPassword}
  │
  ├─ 格式校验 + 密码策略校验（长度/字母+数字）
  ├─ 查找用户（不存在则抛异常）
  ├─ 验证码校验（RESET_PASSWORD 场景）
  ├─ BCrypt encode(newPassword) → 更新 passwordHash
  └─ refreshTokenStore.revokeAll(userId)  # 撤销所有 Refresh Token
      └─ 密码重置后强制所有已登录设备重新登录
```

## 三、JWT 令牌设计

### 3.1 令牌结构

**Access Token Payload（Claims）**：
```json
{
  "iss": "zhiguang",
  "iat": 1735000000,
  "exp": 1735000900,
  "sub": "123456789",
  "jti": "uuid-access-xxx",
  "token_type": "access",
  "uid": 123456789,
  "nickname": "知光用户abc12345"
}
```

**Refresh Token Payload（Claims）**：
```json
{
  "iss": "zhiguang",
  "iat": 1735000000,
  "exp": 1735604800,
  "sub": "123456789",
  "jti": "uuid-refresh-xxx",
  "token_type": "refresh",
  "uid": 123456789
}
```

### 3.2 RS256 非对称签名

- **私钥**（`/keys/private.pem`）：仅后端持有，用于**签发**令牌
- **公钥**（`/keys/public.pem`）：Spring Security Resource Server 使用，用于**校验**令牌
- RS256 相比 HS256 的优势：微服务环境中其他服务只需公钥即可校验，无需共享密钥

### 3.3 Refresh Token 白名单（Redis）

```
Redis Key：refresh_token:{userId}:{tokenId}
Value：（空字符串或任意标识）
TTL：与令牌有效期对齐（≤ 7 天）
```

- 白名单策略（与黑名单相比）：**只有白名单中的 Refresh Token 才有效**
- 登出/重置密码后立即从 Redis 删除对应键，旧令牌立即失效
- `revokeAll(userId)`：通过 `KEYS refresh_token:{userId}:*` 批量删除（生产建议改用 Set 维护）

## 四、Spring Security 配置

### 4.1 路由权限规则

```java
// 公开接口（无需 Token）
.permitAll() → /actuator/health|info
               /api/v1/knowposts/feed         # 首页 Feed
               /api/v1/knowposts/detail/*     # 知文详情
               /api/v1/knowposts/*/qa/stream  # AI 问答 SSE
               /api/v1/auth/send-code|register|login|token/refresh|logout|password/reset

// 其余所有接口
.anyRequest().authenticated()
```

### 4.2 资源服务器配置

```java
.oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
```

Spring Boot 自动读取 `spring.security.oauth2.resourceserver.jwt.*` 配置（或 `AuthConfiguration` 中的 JwtDecoder Bean），对请求 Header 中的 `Authorization: Bearer <token>` 自动完成：
1. Base64 解码 + 签名校验（RS256 公钥）
2. 过期时间校验
3. 注入 `SecurityContextHolder` → 后续可通过 `@AuthenticationPrincipal Jwt jwt` 获取

### 4.3 无状态会话

```java
.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
```

禁用 HttpSession，服务器不保存任何会话状态，天然支持水平扩展。

## 五、验证码系统

### 5.1 场景隔离

| 场景（VerificationScene） | 说明 | 标识存在性要求 |
|--------------------------|------|--------------|
| `REGISTER` | 注册 | 不能已存在 |
| `LOGIN` | 验证码登录 | 必须已存在 |
| `RESET_PASSWORD` | 重置密码 | 必须已存在 |

不同场景的验证码在 Redis 中以不同前缀隔离，互不干扰。

### 5.2 Redis 存储结构

```
Key:    verify:{scene}:{normalizedIdentifier}
Value:  {
            "code": "123456",
            "attempts": 0,
            "createdAt": 1735000000
        }
TTL:    300 秒（可配置）
```

### 5.3 安全保护机制

| 机制 | 说明 |
|------|------|
| **发送频率限制** | 同一标识 60 秒内只能发送一次（Redis TTL 控制） |
| **每日上限** | 同一标识每日最多发送 N 次（Redis 计数器） |
| **尝试次数限制** | 同一验证码最多尝试 5 次，超过标记为 `TOO_MANY_ATTEMPTS` |
| **一次性消费** | 验证成功后立即删除，防止重用 |

### 5.4 验证码状态流转

```
发送成功
    │
    ▼
[NOT_FOUND → 发送后变 PENDING]
    │
    ├── 验证码正确 → SUCCESS（删除记录）
    ├── 验证码错误 → MISMATCH（attempts+1）
    ├── 超过尝试次数 → TOO_MANY_ATTEMPTS
    └── TTL 过期 → NOT_FOUND / EXPIRED
```

## 七、密码安全

### 7.1 存储

使用 **BCrypt** 哈希（`PasswordEncoder` Bean 由 `AuthConfiguration` 注册）：
- 自带 salt，每次 encode 结果不同
- 无法反推原文，泄露数据库也无法获取明文密码

### 7.2 策略校验（validatePassword）

```java
1. 不能为空
2. trim 后长度 ≥ minLength（可配置，默认 8）
3. 必须同时包含字母和数字
```

### 7.3 密码为可选项

注册时密码为**可选**字段——可以纯验证码注册，后续通过"重置密码"设置密码。也可以同时设置密码，支持后续密码登录。

## 九、设计亮点与学习要点

1. **RS256 非对称签名**：私钥签发、公钥校验，天然支持服务解耦
2. **令牌轮换（Refresh Token Rotation）**：每次刷新颁发新令牌对、撤销旧令牌，防重放攻击
3. **白名单策略 vs 黑名单策略**：白名单存储量小（只存活跃令牌），但需要 Redis 访问；黑名单可以纯签名校验，但需要维护过期清理
4. **即时撤销**：Access Token 因为短期（15 分钟）不做撤销；Refresh Token 通过 Redis 白名单支持即时撤销
5. **验证码场景隔离**：同一标识在不同场景（注册/登录/重置密码）的验证码完全隔离
6. **密码为可选**：设计更灵活，支持纯验证码账号体系
