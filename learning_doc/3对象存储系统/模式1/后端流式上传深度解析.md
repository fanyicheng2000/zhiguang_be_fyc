## 一、在看代码之前：先理解对象存储是什么

### 1.1 对象存储 vs 你电脑上的文件系统

你的电脑用文件系统（NTFS/ext4）组织文件：有盘符、有目录、有子目录。

**对象存储（Object Storage）完全不同**，它只有两个概念：

```
┌──────────────────────────────────────────────────┐
│                   存储桶（Bucket）                  │
│                                                  │
│  这是一个平坦的、没有目录层级的"大容器"              │
│                                                  │
│  对象1：key="avatars/123-1735000000.jpg"  value=二进制数据  │
│  对象2：key="posts/456/content.md"        value=二进制数据  │
│  对象3：key="posts/456/images/001.png"    value=二进制数据  │
│                                                  │
│  （key 里的 "/" 只是名字的一部分，不是真正的目录）  │
└──────────────────────────────────────────────────┘
```

**Bucket（存储桶）**：就是这个大容器本身，相当于一个超级大的"平面键值存储"。

**ObjectKey（对象键）**：每个文件的唯一名字，类似文件路径，但本质只是一个字符串 key。

**一句话**：对象存储 = 一个巨大的 `Map<String, byte[]>`，key 是对象键，value 是文件的二进制内容。通过 HTTP 接口来读写这个 Map。

---

### 1.2 阿里云 OSS 的地址结构

阿里云 OSS 的每个文件都有一个 HTTP 地址，格式是：

```
https://{bucket}.{endpoint}/{objectKey}

例：
  bucket   = zhiguangapp
  endpoint = oss-cn-beijing.aliyuncs.com
  objectKey = avatars/123-1735000000.jpg

→ 完整 URL：
  https://zhiguangapp.oss-cn-beijing.aliyuncs.com/avatars/123-1735000000.jpg
```

如果配置了自定义 CDN 域名（`publicDomain = https://cdn.zhiguang.cn`），则变成：

```
https://cdn.zhiguang.cn/avatars/123-1735000000.jpg
```

这两个 URL 指向同一个文件，只是访问入口不同（CDN vs OSS 源站）。

## 二、OssProperties：配置文件的每一项是什么意思

```java
@ConfigurationProperties(prefix = "oss")
public class OssProperties {
    private String endpoint;        // OSS 服务器地址
    private String accessKeyId;     // 账号公钥（身份标识）
    private String accessKeySecret; // 账号私钥（签名密钥，绝密）
    private String bucket;          // 存储桶名称
    private String publicDomain;    // 可选：CDN 自定义域名
    private String folder = "avatars"; // 上传目录前缀（默认值）
}
```

对应 `application.yml` 中：

```yaml
oss:
  endpoint: oss-cn-beijing.aliyuncs.com
  access-key-id: LTAI5tXXXXXXXXX
  access-key-secret: xxxxxxxxxxxxxxxxxxxxxxxx
  bucket: zhiguangapp
  public-domain: https://cdn.zhiguang.cn
  folder: avatars
```

**逐项解释**：

| 配置项 | 类比 | 说明 |
|--------|-----|------|
| `endpoint` | 服务器的域名 | OSS 在哪个地域（北京/上海/深圳），决定请求打到哪个机房 |
| `accessKeyId` | 用户名 | 告诉 OSS "我是谁"，是公开的身份标识 |
| `accessKeySecret` | 密码 | 用来给请求签名，证明"这个请求是我发的"，绝对不能泄漏 |
| `bucket` | 你在 OSS 上申请的那个"大容器"的名字 | 不同业务可以有不同 bucket |
| `publicDomain` | 可选的 CDN 加速域名 | 用 CDN 替代直接访问 OSS 源站，加速文件访问 |
| `folder` | objectKey 的前缀 | 让所有头像文件都以 `avatars/` 开头，方便管理 |

**AccessKeyId + AccessKeySecret 的关系**：

```
类比为 GitHub 的 Personal Access Token：
  - accessKeyId：显示在界面上，可以告诉别人（相当于 token 的"名字"）
  - accessKeySecret：只有你知道，用来加密签名（相当于 token 的值）

OSS 的鉴权机制：
  后端每次发请求时，用 accessKeySecret 对请求内容做 HMAC-SHA1 签名
  OSS 用同一个密钥验证签名，确认请求合法
  → 即使别人知道了你的 accessKeyId，没有 accessKeySecret 也无法伪造请求
```

## 三、OSSClient 是什么：SDK 客户端

`OSSClient` 是阿里云提供的 Java SDK 里的一个类，**本质是一个 HTTP 客户端的封装**。

```
你不用 OSSClient 时，上传文件需要：
  1. 手动构造 HTTP 请求（PUT 方法）
  2. 手动计算 HMAC-SHA1 签名，拼接到 Authorization 头
  3. 手动处理连接、超时、重试
  4. 手动解析 OSS 返回的 XML 响应

用了 OSSClient 之后：
  ossClient.putObject(bucket, key, inputStream)
  ↑ SDK 帮你做了上面所有事，你只需要传入三个参数
```

**OSSClient 的生命周期**（本项目的写法）：

```java
// 每次请求新建一个 OSSClient（创建时建立 HTTP 连接配置）
OSS client = new OSSClientBuilder().build(endpoint, accessKeyId, accessKeySecret);

try {
    // 使用 client 做操作
    client.putObject(...);
} finally {
    // 用完立即关闭（释放底层 HTTP 连接池资源）
    client.shutdown();
}
```

> 注：这种"每次新建+用完关闭"的方式是简单可靠的写法，代价是每次请求都要重新初始化连接配置。生产环境通常会用单例或连接池来复用，但对本项目规模来说这完全够用。

## 四、InputStream 是什么：流式传输的核心

### 4.1 什么是 InputStream

`InputStream` 是 Java 里表示"**可以顺序读取字节的数据源**"的抽象。

```
理解 InputStream 的关键：它不是把数据全部放在内存里，
而是一个"水龙头"——每次 read() 从源头取一段数据出来。

常见的 InputStream 类型：
  FileInputStream        ← 从磁盘文件读
  ByteArrayInputStream   ← 从内存字节数组读
  NetworkInputStream     ← 从网络连接读（前端发来的 HTTP 请求体就是这个）
  file.getInputStream()  ← MultipartFile 的输入流，来自 HTTP 请求体
```

### 4.2 MultipartFile 和它的 InputStream

当前端发送 `multipart/form-data` 请求时，Spring 会把文件部分解析成 `MultipartFile` 对象。

`file.getInputStream()` 返回的是**前端发来的文件数据的字节流**，数据来自网络（前端的 HTTP 请求体），还没有被完整读入后端内存。

```
前端发送：
  POST /api/v1/profile/avatar
  Content-Type: multipart/form-data; boundary=----WebKitFormBoundary

  ------WebKitFormBoundary
  Content-Disposition: form-data; name="file"; filename="avatar.jpg"
  Content-Type: image/jpeg

  [JPEG 文件的二进制数据，比如 150KB]
  ------WebKitFormBoundary--

后端收到：
  MultipartFile file
  file.getOriginalFilename() → "avatar.jpg"
  file.getInputStream()      → 包含那 150KB JPEG 数据的字节流
```

### 4.3 为什么用流而不是先读到内存

用 `InputStream` 传给 OSS SDK，**数据可以边读边发**：

```
不用流的方式（先全部读入内存）：
  byte[] data = file.getBytes();    // 150KB 全部读入 JVM 堆内存
  ossClient.putObject(bucket, key, new ByteArrayInputStream(data));
  // 内存里同时存了两份：请求缓冲区 + byte 数组

用流的方式（边读边发）：
  ossClient.putObject(bucket, key, file.getInputStream());
  // SDK 内部：每次从 InputStream 读一小块（如 8KB），
  //           立即发送给 OSS，发完就丢弃
  // 内存里只需要一块 8KB 的缓冲区，而不是整个文件
```

对于 150KB 的头像，差异不大。但如果是视频文件，流式传输就至关重要了（这也是为什么大文件要用预签名直传，而不是后端中转）。

## 五、ObjectKey：文件的唯一名字是怎么生成的

```java
String original = file.getOriginalFilename();  // → "avatar.jpg"
String ext = "";
if (original != null && original.contains(".")) {
    ext = original.substring(original.lastIndexOf('.'));  // → ".jpg"
}
String objectKey = props.getFolder() + "/" + userId + "-"
                 + Instant.now().toEpochMilli() + ext;
```

假设：
- `props.getFolder()` = `"avatars"`
- `userId` = `123456`
- 当前时间戳 = `1735000000000`（毫秒）
- 文件名 = `"avatar.jpg"`

则：

```
objectKey = "avatars/123456-1735000000000.jpg"
```

**为什么要加时间戳？**

```
防止文件名冲突：
  同一个用户更换头像时，如果 objectKey 固定为 "avatars/123456.jpg"，
  新上传的文件会覆盖旧文件（OSS 行为：同 key 直接覆盖），
  但 CDN 缓存里还是旧文件 → 用户看不到新头像

加了时间戳：
  第一次：avatars/123456-1735000000000.jpg
  第二次：avatars/123456-1735000600000.jpg  ← 不同 key，新文件
  → CDN 也会请求新 URL，不存在缓存问题
  → 旧文件虽然还在 OSS 里，但没有人知道旧 URL，等待定期清理
```

## 六、publicUrl：从 objectKey 到可访问 URL

```java
private String publicUrl(String objectKey) {
    if (props.getPublicDomain() != null && !props.getPublicDomain().isBlank()) {
        // 配置了 CDN 域名：https://cdn.zhiguang.cn/avatars/123-xxx.jpg
        return props.getPublicDomain().replaceAll("/$", "") + "/" + objectKey;
    }
    // 没有 CDN：直接拼 OSS 默认域名
    // https://zhiguangapp.oss-cn-beijing.aliyuncs.com/avatars/123-xxx.jpg
    return "https://" + props.getBucket() + "." + props.getEndpoint() + "/" + objectKey;
}
```

`replaceAll("/$", "")` 的作用是去掉 `publicDomain` 末尾可能多打的斜杠，防止 URL 里出现 `//`。

## 七、完整代码逐行注释

把 `uploadAvatar`、`ProfileController.uploadAvatar`、`ProfileServiceImpl.updateAvatar` 串起来看：

```java
// ─────────────────── Step 1：HTTP 请求到达 Controller ───────────────────

// ProfileController.java
@PostMapping("/avatar")
public ProfileResponse uploadAvatar(
        @AuthenticationPrincipal Jwt jwt,      // Spring Security 注入已验证的 JWT
        @RequestPart("file") MultipartFile file // Spring 解析 multipart 请求中的 "file" 字段
) {
    long userId = jwtService.extractUserId(jwt); // 从 JWT 的 claims 里取出 userId

    // 调用 OssStorageService 上传，拿回 URL
    String url = ossStorageService.uploadAvatar(userId, file);

    // 把 URL 写入数据库 users.avatar 字段
    return profileService.updateAvatar(userId, url);
}


// ─────────────────── Step 2：OssStorageService 上传到 OSS ───────────────────

// OssStorageService.java
public String uploadAvatar(long userId, MultipartFile file) {

    // 校验配置完整性（防止 yaml 里漏了某个字段导致 NPE）
    ensureConfigured();

    // 从原始文件名中提取扩展名（.jpg / .png 等）
    String original = file.getOriginalFilename();
    String ext = "";
    if (original != null && original.contains(".")) {
        ext = original.substring(original.lastIndexOf('.'));  // ".jpg"
    }

    // 生成唯一 objectKey："avatars/123456-1735000000000.jpg"
    String objectKey = props.getFolder() + "/" + userId + "-"
                     + Instant.now().toEpochMilli() + ext;

    // 创建 OSSClient（包含认证信息的 HTTP 客户端）
    OSS client = new OSSClientBuilder().build(
        props.getEndpoint(),       // "oss-cn-beijing.aliyuncs.com"
        props.getAccessKeyId(),    // "LTAI5tXXXX"（账号身份）
        props.getAccessKeySecret() // "xxxxxxxx"（签名密钥）
    );

    try {
        // 构造上传请求
        PutObjectRequest request = new PutObjectRequest(
            props.getBucket(), // 目标 bucket："zhiguangapp"
            objectKey,         // 文件名："avatars/123456-1735000000000.jpg"
            file.getInputStream() // 文件数据的字节流
        );

        // 发出 HTTP PUT 请求到 OSS
        // SDK 内部：计算签名 → 发送 PUT 请求 → 等待响应 → 解析结果
        client.putObject(request);

    } catch (IOException e) {
        throw new BusinessException(ErrorCode.BAD_REQUEST, "头像文件读取失败");
    } finally {
        client.shutdown(); // 无论成功失败，都释放 HTTP 连接资源
    }

    // 返回可公开访问的 URL（CDN 域名 或 OSS 默认域名）
    return publicUrl(objectKey);
}


// ─────────────────── Step 3：把 URL 写入数据库 ───────────────────

// ProfileServiceImpl.java
public ProfileResponse updateAvatar(long userId, String avatarUrl) {
    // 只更新 avatar 字段，其他字段不动
    User patch = new User();
    patch.setId(userId);
    patch.setAvatar(avatarUrl); // "https://cdn.zhiguang.cn/avatars/123456-xxx.jpg"
    userMapper.updateProfile(patch); // UPDATE users SET avatar=? WHERE id=?

    // 重新查一次，返回最新状态（包含新头像 URL）
    User updated = userMapper.findById(userId);
    return toResponse(updated);
}
```

## 八、OSSClient 发出的 HTTP 请求长什么样

`client.putObject(request)` 实际上向 OSS 发出了这样一个 HTTP 请求：

```
PUT /avatars/123456-1735000000000.jpg HTTP/1.1
Host: zhiguangapp.oss-cn-beijing.aliyuncs.com
Date: Wed, 20 May 2026 10:00:00 GMT
Content-Type: image/jpeg
Content-Length: 153600
Authorization: OSS LTAI5tXXXX:ZkJhb2XXXXXXXXX=   ← HMAC-SHA1 签名

[153600 字节的 JPEG 二进制数据]
```

OSS 收到请求后：
1. 从 `Authorization` 头里读出 `accessKeyId`（`LTAI5tXXXX`），找到对应的 `accessKeySecret`
2. 用相同的算法重新计算签名，与请求中的签名比对
3. 签名匹配 → 把请求体（JPEG 数据）存储到 `zhiguangapp` 这个 bucket 的 `avatars/123456-1735000000000.jpg` 这个 key 下
4. 返回 `200 OK`，附带文件的 ETag（MD5 值）

## 九、调用 OSSClient 算 RPC 吗？

这是个非常好的问题，值得认真回答。

### 什么是 RPC

**RPC（Remote Procedure Call，远程过程调用）** 的本质是：**像调用本地函数一样调用远程服务的方法**，调用方感知不到网络的存在。

狭义的 RPC 通常指使用专用二进制协议的框架，如 gRPC（HTTP/2 + Protobuf）、Dubbo（自定义 TCP 协议）、Thrift 等。

### OSSClient 算不算

```
OSSClient.putObject(...)
↓
SDK 内部将调用翻译成 HTTP PUT 请求
↓
通过 TCP 连接发到阿里云 OSS 服务器
↓
等待响应
↓
返回结果

这是一次网络调用，底层是 HTTP（而不是 Protobuf/Thrift 等 RPC 协议）。
```

**从广义上说：算。**
- 你在本地 Java 代码里调用了 `client.putObject()`
- 实际执行的是阿里云数据中心里的 OSS 服务
- 你的代码感知不到内部细节，就像调用本地函数一样

**从狭义上说：不算，更准确的说法是"HTTP API 调用"。**
- RPC 通常指使用专用二进制协议（gRPC/Dubbo/Thrift）的框架
- OSS SDK 底层是标准 HTTP/HTTPS，遵循 REST 风格（PUT/GET/DELETE 对应创建/读取/删除）
- 业界一般把这类调用称为 **HTTP 调用**、**REST API 调用**，或者说**调用了第三方服务**

### 总结

| 调用方式 | 例子 | 习惯叫法 |
|---------|------|---------|
| gRPC | 调用另一个微服务的接口 | RPC 调用 |
| Dubbo/Thrift | 同上 | RPC 调用 |
| HTTP REST（内部服务） | Spring Boot 间通过 OpenFeign 调用 | HTTP 调用 / RPC 调用（广义） |
| HTTP REST（第三方服务） | 调用 OSS SDK、支付宝 SDK、微信 SDK | **第三方 HTTP API 调用** |

调用 OSSClient 更准确的说法是：**通过 OSS Java SDK 向阿里云 OSS 发起了一次 HTTP API 调用**。它确实是网络调用，但不属于常说的"RPC"范畴。

## 十、整个流程的完整全景图

```
前端 (浏览器/App)
  │
  │  POST /api/v1/profile/avatar
  │  Authorization: Bearer <JWT>
  │  Content-Type: multipart/form-data
  │  Body: [JPEG 文件二进制]
  │
  ▼
后端 (ProfileController)
  │
  ├─ Spring Security 验证 JWT ✓
  ├─ 解析 JWT 取 userId = 123456
  │
  ▼
OssStorageService.uploadAvatar(123456, file)
  │
  ├─ 从 OssProperties 读取配置
  │    endpoint / accessKeyId / accessKeySecret / bucket / folder
  │
  ├─ 生成 objectKey = "avatars/123456-1735000000000.jpg"
  │
  ├─ new OSSClientBuilder().build(endpoint, keyId, secret)
  │    → 创建一个配置好的 HTTP 客户端
  │
  ├─ file.getInputStream()
  │    → 拿到前端发来的 JPEG 字节流（不是全部读进内存，是流）
  │
  ├─ client.putObject(bucket, objectKey, inputStream)
  │    SDK 内部：
  │    ① 用 accessKeySecret 计算 HMAC-SHA1 签名
  │    ② 发出 HTTP PUT 请求（携带签名 + 文件字节流）
  │    ③ 等待 OSS 响应 200 OK
  │
  │  ┌──────────────────────────────────────┐
  │  │         阿里云 OSS 服务器              │
  │  │  验证签名 ✓                          │
  │  │  存储文件到 zhiguangapp/avatars/...   │
  │  │  返回 200 OK                         │
  │  └──────────────────────────────────────┘
  │
  ├─ client.shutdown()  释放连接资源
  │
  ├─ publicUrl(objectKey)
  │    → "https://cdn.zhiguang.cn/avatars/123456-1735000000000.jpg"
  │
  ▼
ProfileServiceImpl.updateAvatar(123456, url)
  │
  ├─ UPDATE users SET avatar='https://cdn...' WHERE id=123456
  │
  ▼
返回 ProfileResponse（包含新头像 URL）给前端
