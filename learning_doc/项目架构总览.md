# 知光平台后端 — 项目架构总览

> 知光平台（ZhiGuang）是一款知识获取与分享社区 APP，支持发布知识、点赞/收藏、关注取关、首页 Feed 展示与对象存储直传，以及 AI 生成摘要等功能。

---

## 一、技术栈总览

| 分层 | 技术选型 |
|------|---------|
| 语言/框架 | Java 21 + Spring Boot 3.x |
| 安全 | Spring Security + OAuth2 Resource Server（JWT/RS256） |
| AI | Spring AI + DeepSeek（RAG 问答 + 摘要生成） |
| 持久层 | MyBatis + MySQL |
| 缓存 | Redis（StringRedisTemplate / Redisson）+ Caffeine（本地缓存） |
| 消息队列 | Kafka（异步事件、写聚合、灾难回放） |
| 搜索 | Elasticsearch（全文检索 + 向量库） |
| 对象存储 | 阿里云 OSS（预签名 PUT 直传） |
| 变更捕获 | Canal（订阅 MySQL binlog → Kafka） |

## 四、各模块简介

### 4.1 认证系统（auth）
基于 Spring Security OAuth2 Resource Server 的 **JWT 双令牌认证**。
- **Access Token**：RS256 签名，有效期 15 分钟，携带 `uid`/`nickname`/`token_type`
- **Refresh Token**：RS256 签名，有效期 7 天，基于 Redis 白名单管理，支持即时撤销
- 支持手机号/邮箱登录，密码或验证码两种通道
- 详见 [认证系统.md](./认证系统.md)

### 4.2 知文发布与 Feed 流（knowpost）
采用**渐进式发布流程**（createDraft → confirmContent → updateMetadata → publish），正文/图片存入 OSS，前端直传。Feed 流采用**三级缓存架构**（Caffeine → Redis 片段缓存 → MySQL），配合 SingleFlight 单飞锁防击穿，热点探测自动延长 TTL。
- 详见 [知文发布与Feed流系统.md](./知文发布与Feed流系统.md)

### 4.3 计数与点赞系统（counter）
点赞/收藏以 **Redis 分片位图**（Bitmap Shard）存储，Lua 脚本原子切换保证幂等。计数汇总（SDS）采用大端 32 位二进制紧凑编码。读取时若 SDS 异常则触发基于位图的**按需重建**，配合 Redisson 分布式锁 + 指数退避限流防止风暴。Kafka 聚合消费者批量更新 SDS。
- 详见 [计数与点赞系统.md](./计数与点赞系统.md)

### 4.4 用户关系系统（relation）
**一主多从 + 事件驱动**架构。关注/取消关注写入 MySQL following 表的同一事务中同时写 Outbox 表；Canal 订阅 Outbox binlog → Kafka，异步更新粉丝表、Redis ZSet 列表缓存、用户计数 SDS。大V 用户（粉丝数 ≥ 50 万）启用 Caffeine 本地 Top 缓存。
- 详见 [用户关系系统.md](./用户关系系统.md)

### 4.5 搜索系统（search）
基于 Elasticsearch 构建。**关键词检索**使用 `multi_match`（title 字段权重 ×3，body 字段）+ `function_score` 融合 BM25 相关性与点赞数/浏览数业务权重。分页采用 `search_after` 游标机制保证深分页稳定性。**联想建议**使用 ES Completion Suggester 实现低延迟前缀联想。
- 详见 [搜索系统.md](./搜索系统.md)

### 4.6 AI 问答与 RAG 系统（llm）
基于 Spring AI + DeepSeek 模型构建知文维度的 RAG 知识问答。流程：索引检查（指纹/SHA256）→ 向量检索（ES VectorStore）→ Prompt 构造 → DeepSeek 流式生成（SSE）。Markdown 正文按标题切段 + 固定长度切片（800字/块，100字重叠），支持幂等重建（delete-by-query）。
- 详见 [AI问答与RAG系统.md](./AI问答与RAG系统.md)

### 4.7 对象存储系统（storage）
使用阿里云 OSS。支持两种上传方式：
1. 后端流式上传（头像直接上传，多部分表单）
2. **预签名 PUT URL 直传**（知文图片/视频/Markdown 正文，节省后端带宽）
- 详见 [对象存储系统.md](./对象存储系统.md)

### 4.8 个人资料系统（profile）
支持 PATCH 部分更新（nickname/bio/gender/birthday/zgId/school/tagJson），动态 SQL 仅写非空字段，zgId 做唯一性排他检查。头像通过后端上传 OSS 后更新 URL。

### 4.9 公共基础设施
- **Outbox 模式**：关系变更/内容变更通过 Outbox 表 + Canal + Kafka 实现最终一致性事件驱动
- **全局异常处理**：`BusinessException`（带 `ErrorCode`）→ HTTP 400；`@Valid` 校验失败 → HTTP 400；兜底 → HTTP 500
- **线程池**：核心 10/最大 50/队列 200，CallerRunsPolicy，优雅关闭等待 60 秒

## 五、关键设计模式汇总

| 模式 | 应用场景 |
|------|---------|
| **Outbox 模式** | 关注/取关事件、知文发布/删除事件的最终一致性保障 |
| **SingleFlight（单飞锁）** | Feed 流分页/知文详情缓存击穿防护 |
| **分片位图（Bitmap Shard）** | 点赞/收藏幂等判重 + 计数按需重建 |
| **三级缓存** | Caffeine L1 → Redis 片段缓存 L2 → MySQL L3 |
| **热点探测（HotKey Detector）** | 自动按访问频率延长热点内容缓存 TTL |
| **Redis ZSet** | 关注/粉丝列表游标分页缓存 |
| **令牌桶限流（Lua）** | 关注操作频率限制 |
| **指数退避** | SDS 重建失败时的保护策略 |
| **JWT 双令牌白名单** | 安全会话管理 + 即时令牌撤销 |
| **search_after 游标** | ES 深分页稳定性保证 |
| **预签名直传** | 节省后端带宽 + 降低延迟 |
| **RS256 非对称签名** | JWT 高安全性，私钥签发/公钥校验解耦 |
| **RAG（检索增强生成）** | 知文维度精准 AI 问答 |

## 六、数据库核心表

| 表名 | 说明 |
|------|------|
| `users` | 用户主表（phone/email/nickname/avatar/zgId 等） |
| `know_posts` | 知文主表（status/visible/contentUrl/imgUrls/tags 等） |
| `following` | 关注关系表（fromUserId/toUserId/rel_status） |
| `follower` | 粉丝表（由 Canal Outbox 事件异步维护） |
| `outbox` | 事件发件箱（aggregate_type/aggregate_id/type/payload） |
| `login_logs` | 登录审计日志（user_id/channel/ip/user_agent/status） |
