# 注册流程详解

> 注册分为两个独立的 HTTP 请求：先发送验证码，再提交注册。本文把两个请求的后端处理过程都拆解清楚。

---

## 一、整体流程概览

```
前端                                    后端
 │                                       │
 │  第一步：发送验证码                   │
 │  POST /api/v1/auth/send-code          │
 │  { scene:"REGISTER", identifierType:"PHONE", identifier:"138xxxx" }
 │ ─────────────────────────────────────►│
 │                                       │  格式校验 → 账号存在性检查
 │                                       │  → 发送频率/日限额限制
 │                                       │  → 生成验证码 → 存 Redis
 │                                       │  → 发送（打日志）
 │ ◄─────────────────────────────────────│
 │  { identifier, scene, expireSeconds } │
 │                                       │
 │  用户收到验证码，填写表单...           │
 │                                       │
 │  第二步：提交注册                     │
 │  POST /api/v1/auth/register           │
 │  { identifierType, identifier, code, password?, agreeTerms:true }
 │ ─────────────────────────────────────►│
 │                                       │  agreeTerms 检查
 │                                       │  → 格式校验 → 账号唯一性校验
 │                                       │  → 验证码校验（查 Redis）
 │                                       │  → 密码策略校验（可选）
 │                                       │  → 创建用户（写 MySQL）
 │                                       │  → 签发令牌对（JWT）
 │                                       │  → 白名单存储（Redis）
 │                                       │  → 记录审计日志（MySQL）
 │ ◄─────────────────────────────────────│
 │  { user:{...}, token:{accessToken, refreshToken, ...} }
 │                                       │
```

## 二、第一步：发送验证码

### 接口信息

```
POST /api/v1/auth/send-code
（SecurityConfig 中配置为 permitAll，无需登录）
```

### 请求体

```java
// SendCodeRequest.java
public record SendCodeRequest(
    VerificationScene scene,        // REGISTER / LOGIN / RESET_PASSWORD
    IdentifierType identifierType,  // PHONE 或 EMAIL
    String identifier               // 手机号或邮箱
) {}
```

注册时前端传 `scene = REGISTER`。

### 后端处理：AuthService.sendCode()

```java
public SendCodeResponse sendCode(SendCodeRequest request) {
    // ① 格式校验
    validateIdentifier(request.identifierType(), request.identifier());

    // ② 标准化：手机号去空格 / 邮箱转小写+去空格
    String normalized = normalizeIdentifier(request.identifierType(), request.identifier());

    // ③ 账号存在性检查（注册场景要求账号不存在）
    boolean exists = identifierExists(request.identifierType(), normalized);
    if (request.scene() == VerificationScene.REGISTER && exists) {
        throw new BusinessException(ErrorCode.IDENTIFIER_EXISTS);  // 账号已注册
    }

    // ④ 发送验证码（含速率限制）
    SendCodeResult result = verificationService.sendCode(request.scene(), normalized);

    return new SendCodeResponse(result.identifier(), result.scene(), result.expireSeconds());
}
```

**步骤①：格式校验（IdentifierValidator）**

```java
// IdentifierValidator.java
// 手机号：中国大陆 11 位，以 1 开头
private static final Pattern PHONE_PATTERN = Pattern.compile("^1\\d{10}$");
// 邮箱：大小写不敏感的标准邮箱格式
private static final Pattern EMAIL_PATTERN = Pattern.compile(
    "^[A-Z0-9._%+-]+@[A-Z0-9.-]+\\.[A-Z]{2,}$", Pattern.CASE_INSENSITIVE);
```

格式不合法直接抛 `BusinessException(BAD_REQUEST)`，请求终止。

**步骤②：标准化**

- 手机号：`identifier.trim()`（去首尾空格）
- 邮箱：`identifier.trim().toLowerCase()`（去空格并转小写）

标准化后的值才会存入 Redis / 查询数据库，保证同一个账号格式统一。

**步骤③：存在性检查**

注册场景特有逻辑：如果账号已经注册过，直接返回错误，不发验证码（防止骚扰已有用户）。登录/重置密码场景则相反——账号不存在才报错。

### VerificationService.sendCode()：速率限制 + 生成 + 存储 + 发送

```java
public SendCodeResult sendCode(VerificationScene scene, String identifier) {
    AuthProperties.Verification cfg = properties.getVerification();

    // ① 发送间隔限制（默认 60 秒）
    enforceSendInterval(scene, identifier, cfg.getSendInterval());

    // ② 每日发送次数限制（默认 10 次）
    enforceDailyLimit(scene, identifier, cfg.getDailyLimit());

    // ③ 生成随机数字验证码（默认 6 位）
    String code = generateNumericCode(cfg.getCodeLength());

    // ④ 存入 Redis（有效期 5 分钟，最多 5 次尝试）
    codeStore.saveCode(scene.name(), identifier, code, cfg.getTtl(), cfg.getMaxAttempts());

    // ⑤ 发送（当前实现：打日志，生产环境替换为短信/邮件服务）
    codeSender.sendCode(scene, identifier, code, (int) cfg.getTtl().toMinutes());

    return new SendCodeResult(identifier, scene, (int) cfg.getTtl().toSeconds());
}
```

**发送间隔限制（60 秒冷却）**

```java
private void enforceSendInterval(VerificationScene scene, String identifier, Duration interval) {
    String key = "auth:code:last:REGISTER:138xxxx";  // 示例键
    String existing = stringRedisTemplate.opsForValue().get(key);
    if (existing != null) {
        throw new BusinessException(ErrorCode.VERIFICATION_RATE_LIMIT);  // 60 秒内已发过
    }
    // 写入冷却标记，TTL = 60 秒
    stringRedisTemplate.opsForValue().set(key, "1", interval);
}
```

**每日次数限制（每日最多 10 次）**

```java
private void enforceDailyLimit(VerificationScene scene, String identifier, int limit) {
    String date = "20260517";  // 当天日期
    String key = "auth:code:count:REGISTER:138xxxx:20260517";  // 示例键
    Long count = stringRedisTemplate.opsForValue().increment(key);  // 原子自增
    if (count == 1L) {
        stringRedisTemplate.expire(key, Duration.ofDays(1));  // 首次自增时设置 1 天 TTL
    }
    if (count > limit) {
        throw new BusinessException(ErrorCode.VERIFICATION_DAILY_LIMIT);
    }
}
```

**验证码存储结构（Redis Hash）**

```java
// RedisVerificationCodeStore.saveCode()
// 键名：auth:code:REGISTER:138xxxx
// Hash 结构：
//   code        → "483920"   （验证码明文）
//   maxAttempts → "5"        （最大尝试次数）
//   attempts    → "0"        （当前已尝试次数）
// TTL：5 分钟
```

为什么用 Hash 而不是 String？因为需要同时存储验证码值和尝试计数，Hash 可以原子读写多个字段。

**发送实现**

当前是 `LoggingCodeSender`，只打日志，不真正发短信/邮件：

```java
// LoggingCodeSender.java
public void sendCode(VerificationScene scene, String identifier, String code, int expireMinutes) {
    log.info("Send verification code scene={} identifier={} code={} expireMinutes={}",
             scene, identifier, code, expireMinutes);
    // 生产环境：替换为调用短信平台 SDK 或邮件服务
}
```

### 响应体

```json
{

  "scene": "REGISTER",
  "expireSeconds": 300

```

## 三、第二步：提交注册

### 接口信息

```
POST /api/v1/auth/register
（SecurityConfig 中配置为 permitAll，无需登录）
```

### 请求体

```java
// RegisterRequest.java
public record RegisterRequest(
    @NotNull  IdentifierType identifierType,  // PHONE / EMAIL
    @NotBlank String identifier,              // 手机号或邮箱
    @NotBlank String code,                    // 验证码（必填）
    String password,                          // 密码（可选，不填则只能验证码登录）
    boolean agreeTerms                        // 是否同意服务条款
) {}
```

`password` 是可选的：本项目支持"仅验证码登录"的账号，注册时可以不设置密码。

### 后端处理：AuthController → AuthService.register()

Controller 层除了转发请求，还额外提取了客户端信息（用于审计日志）：

```java
// AuthController.java
@PostMapping("/register")
public AuthResponse register(@Valid @RequestBody RegisterRequest request,
                             HttpServletRequest httpRequest) {
    return authService.register(request, resolveClient(httpRequest));
}

private ClientInfo resolveClient(HttpServletRequest request) {
    String ip = extractClientIp(request);  // 优先 X-Forwarded-For，其次 X-Real-IP
    String ua = request.getHeader("User-Agent");
    return new ClientInfo(ip, ua);
}
```

### AuthService.register()：完整注册逻辑

```java
public AuthResponse register(RegisterRequest request, ClientInfo clientInfo) {

    // ① 协议同意检查
    if (!request.agreeTerms()) {
        throw new BusinessException(ErrorCode.TERMS_NOT_ACCEPTED);
    }

    // ② 格式校验 + 标准化
    validateIdentifier(request.identifierType(), request.identifier());
    String identifier = normalizeIdentifier(request.identifierType(), request.identifier());

    // ③ 账号唯一性二次校验（防止发送验证码到提交注册期间被抢注）
    if (identifierExists(request.identifierType(), identifier)) {
        throw new BusinessException(ErrorCode.IDENTIFIER_EXISTS);
    }

    // ④ 验证码校验
    ensureVerificationSuccess(
        verificationService.verify(VerificationScene.REGISTER, identifier, request.code())
    );

    // ⑤ 构建用户对象
    User user = User.builder()
        .phone(request.identifierType() == IdentifierType.PHONE ? identifier : null)
        .email(request.identifierType() == IdentifierType.EMAIL ? identifier : null)
        .nickname(generateNickname())   // "知光用户" + UUID 前8位
        .avatar("https://static.zhiguang.cn/default-avatar.png")
        .tagsJson("[]")
        .build();

    // ⑥ 可选：密码策略校验 + BCrypt 哈希
    if (StringUtils.hasText(request.password())) {
        validatePassword(request.password());
        user.setPasswordHash(passwordEncoder.encode(request.password().trim()));
    }

    // ⑦ 写入数据库（MySQL）
    userService.createUser(user);

    // ⑧ 签发 JWT 令牌对
    TokenPair tokenPair = jwtService.issueTokenPair(user);

    // ⑨ Refresh Token 存入 Redis 白名单
    storeRefreshToken(user.getId(), tokenPair);

    // ⑩ 记录审计日志
    loginLogService.record(user.getId(), identifier, "REGISTER",
                           clientInfo.ip(), clientInfo.userAgent(), "SUCCESS");

    // ⑪ 组装响应
    return new AuthResponse(mapUser(user), mapToken(tokenPair));
}
```

### 步骤④：验证码校验（RedisVerificationCodeStore.verify）

```java
// VerificationService.verify() 最终调用
public VerificationCheckResult verify(String scene, String identifier, String code) {
    String key = "auth:code:REGISTER:138xxxx";
    Map<String, String> data = ops.entries(key);  // 读取 Hash 全部字段

    if (data.isEmpty()) {
        return new VerificationCheckResult(NOT_FOUND, 0, 0);  // 从未发送或已过期
    }

    String storedCode = data.get("code");         // 存储的验证码
    int maxAttempts = parseInt(data.get("maxAttempts"), 5);  // 最大尝试次数 = 5
    int attempts    = parseInt(data.get("attempts"), 0);     // 已尝试次数

    // 已超出尝试次数上限
    if (attempts >= maxAttempts) {
        return new VerificationCheckResult(TOO_MANY_ATTEMPTS, attempts, maxAttempts);
    }

    // 验证码匹配 → 成功，立即删除键（防止重用）
    if (Objects.equals(storedCode, code)) {
        redisTemplate.delete(key);
        return new VerificationCheckResult(SUCCESS, attempts, maxAttempts);
    }

    // 验证码不匹配 → 自增尝试计数
    int updatedAttempts = attempts + 1;
    ops.put(key, "attempts", String.valueOf(updatedAttempts));

    // 到达上限时，延长 TTL 至 30 分钟（防止立刻过期后重新发码绕过锁定）
    if (updatedAttempts >= maxAttempts) {
        redisTemplate.expire(key, Duration.ofMinutes(30));
        return new VerificationCheckResult(TOO_MANY_ATTEMPTS, updatedAttempts, maxAttempts);
    }

    return new VerificationCheckResult(MISMATCH, updatedAttempts, maxAttempts);
}
```

校验结果到业务层的映射：

```java
// AuthService.ensureVerificationSuccess()
private void ensureVerificationSuccess(VerificationCheckResult result) {
    if (result.isSuccess()) return;
    switch (result.status()) {
        case NOT_FOUND, EXPIRED  -> throw new BusinessException(VERIFICATION_NOT_FOUND);   // 验证码不存在/已过期
        case MISMATCH            -> throw new BusinessException(VERIFICATION_MISMATCH);     // 验证码错误
        case TOO_MANY_ATTEMPTS   -> throw new BusinessException(VERIFICATION_TOO_MANY_ATTEMPTS); // 错误次数过多
    }
}
```

验证码成功后 Redis 键立即被删除，保证**一次性使用**，不能用同一个验证码注册两个账号。

### 步骤⑥：密码策略校验

```java
private void validatePassword(String password) {
    String trimmed = password.trim();
    // 最小长度：8 位（来自配置 auth.password.min-length）
    if (trimmed.length() < authProperties.getPassword().getMinLength()) {
        throw new BusinessException(PASSWORD_POLICY_VIOLATION, "密码长度至少8位");
    }
    // 必须同时包含字母和数字
    boolean hasLetter = trimmed.chars().anyMatch(Character::isLetter);
    boolean hasDigit  = trimmed.chars().anyMatch(Character::isDigit);
    if (!hasLetter || !hasDigit) {
        throw new BusinessException(PASSWORD_POLICY_VIOLATION, "密码需包含字母和数字");
    }
}
```

通过校验后，用 BCrypt 哈希存储（强度 12，来自 `auth.password.bcrypt-strength`）：

```java
user.setPasswordHash(passwordEncoder.encode(request.password().trim()));
// BCrypt 输出示例：$2a$12$XXXXX...（60 位哈希字符串）
// 注意：BCrypt 每次生成的哈希值不同（包含随机盐），但 matches() 可以正确验证
```

这两步在"JWT 令牌如何返回给前端"和"令牌刷新流程详解"中已有详细说明，此处简述：

```java
// 将 Refresh Token 的 jti 写入 Redis 白名单
// 键：auth:rt:{userId}:{jti}，值："1"，TTL = 剩余有效时长
```

### 步骤⑩：审计日志

```java
loginLogService.record(
    user.getId(),      // 用户 ID
    identifier,        // 注册账号（手机号/邮箱）
    "REGISTER",        // 渠道标识
    clientInfo.ip(),   // 客户端 IP（从 X-Forwarded-For / X-Real-IP / remoteAddr 提取）
```

注意：注册流程中**只有成功才记录审计**（没有像登录那样在密码错误时记录 FAILED）。如果中途任何步骤抛出异常，事务回滚，审计日志不会写入。

## 四、两步流程中的 Redis 键全景

```
发送验证码后，Redis 里存在以下键：

auth:code:last:REGISTER:138xxxx       → "1"，TTL = 60 秒（冷却标记）
auth:code:count:REGISTER:138xxxx:20260517  → "1"，TTL = 1 天（当日发送计数）
auth:code:REGISTER:138xxxx            → Hash { code:"483920", maxAttempts:"5", attempts:"0" }
                                          TTL = 5 分钟（验证码本体）

注册成功后：

auth:code:REGISTER:138xxxx            → 已删除（验证成功后立即清除）
auth:rt:10001:550e8400-...            → "1"，TTL = 7 天（Refresh Token 白名单）
```

## 五、关键防护机制汇总

| 防护点 | 实现方式 | 位置 |
|---|---|---|
| 账号格式非法 | 正则校验（手机 `^1\d{10}$`，邮箱标准格式） | `IdentifierValidator` |
| 账号已注册（发码阶段） | 发码前查库，REGISTER 场景要求账号不存在 | `AuthService.sendCode()` |
| 验证码发送频率（60 秒冷却） | Redis TTL 60 秒的冷却键，存在即拦截 | `VerificationService.enforceSendInterval()` |
| 验证码每日发送上限（10 次） | Redis 计数器原子自增，超限即拦截 | `VerificationService.enforceDailyLimit()` |
| 未同意服务条款 | 提交注册时检查 `agreeTerms == true` | `AuthService.register()` |
| 账号已注册（提交阶段）| 发码到提交期间可能被抢注，二次校验 | `AuthService.register()` |
| 验证码错误（最多 5 次） | Redis Hash 记录尝试次数，超限后延长 TTL 30 分钟 | `RedisVerificationCodeStore.verify()` |
| 验证码重复使用 | 验证成功后立即删除 Redis 键 | `RedisVerificationCodeStore.verify()` |
| 密码强度不足 | 最小 8 位 + 必须含字母和数字 | `AuthService.validatePassword()` |
| 密码明文存储 | BCrypt 哈希（强度 12），不可逆 | `AuthService.register()` |

---

## 六、一句话总结

> 注册 = 先发验证码（双重速率限制 + Redis Hash 存码）→ 再提交（协议检查 → 格式校验 → 二次唯一性校验 → 验证码校验 → 可选密码哈希 → 创建用户 → 自动登录签发令牌）。全程无 Session，状态全靠 Redis 键管理。
